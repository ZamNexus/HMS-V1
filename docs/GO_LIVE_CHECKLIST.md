# Go-live checklist (frontend)

The 13 items of the handoff's section 10, each with its status and the evidence that backs it. Updated 2026-11-08 (Phase 12).

**Legend.** DONE = built and checked in this repository (unit tests, the API-mode browser suites against the test backends, the build). NOT VERIFIED = built, but the check needs something this repository does not have (a real server, a printer, a host). NOT DONE = a gap, with what closes it.

**Nothing here has been run against a real backend.** The browser suites use stateful test backends (`e2e-api/fakes`) that validate every request and response against `docs/openapi.json`; they prove the screens behave as the handoff describes, not that the real server does.

## What blocks go-live

1. Item 12 and the real-server half of item 2: dev credentials (N2), role accounts (N3), the dev API available.
2. Item 11: the production host and `TRUST_PROXY_HOPS` (N5).
3. Item 9 on the hospitals' printers.
4. The ten chunks built in Phase 13 (expenses, bank, cash drawer, dashboard, five reports, prescription history, statistics Summary / Graphs) against the real backend: the handoff gives their requests but not the fields of their answers, so the first real answers must be compared with SPEC_BUGS_FOR_BACKEND.md section 9 (the screens read defensively and show the rest as received, so a different shape shows up as an extra or missing column rather than a crash, except where an answer lacks an id, a day or a money amount, which is refused with an error).

## Not available at launch (handoff section 10, unchanged)

Patient, doctor and clinic photos (file storage T13): initials are shown and the upload is hidden in API mode. Imaging image upload (PACS): out of scope. Medicine packages and GST on medicines: waiting on a hospital decision. Commission payouts: no screen.
